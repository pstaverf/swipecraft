# Ивенты (этап 4)

Этап 4 добавляет в Swipecraft планировщик ивентов с персистентным состоянием и семь механик. Все ивенты живут в Script API 2.11.0: каждая функция сверена с `@minecraft/server` 2.11.0 из `node_modules`. Чат-хуков, отмены постановки блока и `Player.kick()` в этой версии нет — механики построены только на существующих событиях.

## 1. Расписание

| Параметр | Значение | Где менять |
|---|---|---|
| Интервал | 6 часов между финишем и стартом | `EVENT_SCHEDULE.intervalMs` (`src/events/config.ts`) |
| Минимум игроков | 3 (на ивент) | `EVENT_SCHEDULE.minPlayers` и `EVENTS.<id>.minPlayers` |
| Перенос при пустом сервере | +15 минут, максимум 8 переносов, затем пауза 30 минут | `postponeMs`, `maxPostpones` |
| Анонс | титр + звук за 5 минут и за 1 минуту | `announceLead5Ms`, `announceLead1Ms` |
| Ротация | без повторов последних 3 ивентов | `rotationMemory` |
| Награды | не меньше 5 минут в мире и аккаунт старше 10 минут | `minPlaySecondsForRewards`, `minAccountAgeMs` |
| Пустой сервер во время ивента | 5 минут без игроков → ивент закрывается как `empty`, награды не выдаются | `EMPTY_GRACE_MS` |

Планировщик — задача тикера `events-scheduler` (интервал 20 тиков = 1 секунда, бюджет 5 мс). Каждый тик проверяет: активный ивент → `tick()` обработчика; иначе — время до следующего ивента, анонсы, запуск.

## 2. Состояние и восстановление после падения

Состояние хранится в dynamic properties мира одним JSON-документом `sw:events` (чанки `sw:events:0…n` + `sw:events:n`, см. `src/kernel/store.ts`):

```ts
interface PersistentEvents {
  history: EventId[];        // последние 12 ивентов
  nextAt: number;            // epoch ms старта следующего
  planned: EventId;          // запланированный ивент (для анонсов)
  postponed: number;         // сколько раз подряд перенесли
  active?: ActiveEvent;      // идущий ивент: id, startedAt, endsAt, manual, data
  announced5: number;        // для кого уже анонсировали 5 минут
  announced1: number;
  emptySince: number;
  lastFinishedAt: number;
  pending: PendingReward[];  // отложенные награды
}
```

Матрица поведения при старте сервера (`recover()` в `src/events/manager.ts`):

| Ситуация | Поведение |
|---|---|
| Ивент шёл, `endsAt` в будущем | Продолжаем: `handler.resume()` (кровавая луна снова ставит ночь), состояние зон/босса берётся из `active.data`, игрокам при входе приходит «Сейчас идёт ивент: …» |
| Ивент шёл, `endsAt` в прошлом | Завершаем с компенсацией: `handler.finish(active, "recover")`; KOTH отдаёт награду держателю при прогрессе ≥ 50 %, босс-рейд выплачивает по сохранённому урону |
| Награда положена, игрок офлайн | Пишется в `pending`, выдаётся при следующем входе (сообщение «Награда за ивент, пока тебя не было»), хранится 7 дней |
| Активного не было | Планируется следующий по `nextAt`, история сохраняется |

Дополнительно: `events-scheduler` не даёт двойных выплат — на каждого игрока на каждый ивент ставится флаг в `active.data.awarded`, `grantLoot()` отказывает повторно.

## 3. Ивенты

### 3.1 Аирдроп (`airdrop`)

- **Механика:** в кольце 150–1400 блоков от центра (внутри текущей границы) выбирается точка на поверхности, 8 секунд падает световой столб (`minecraft:endrod`), затем ставится сундук с лутом. Координаты объявляются в чате.
- **Конфиг:** `EVENTS.airdrop` — `durationMs` 15 мин, `fallMs` 8000, радиусы, `loot`.
- **Конец:** по таймауту сундук остаётся в мире (лут не пропадает). При ручной отмене сундук не ставится, если ещё не приземлился.
- **Пустой сервер:** не стартует (< 3 игроков), переносится.
- **Риски:** `getTopmostBlock()` может вернуть воду или листву — сундук окажется в воде/на дереве; повторные попытки (12) снижают вероятность. Точка не проверяется на постройки игроков.

### 3.2 Кровавая луна (`bloodmoon`)

- **Механика:** `world.setTimeOfDay(18000)`, каждые 25 секунд спавнится волна из 3 мобов рядом со случайными игроками (зомби, скелет, паук, кадавр) с тегом `sw:bloodmoon`, силой II, скоростью I, сопротивлением I. Убийство меченого моба даёт 55 % шанс бонусного лута.
- **Конфиг:** `EVENTS.bloodmoon` — длительность 20 мин, `waveEveryMs`, `waveSize`, `mobs`, `bonusChance`, `bonusLoot`.
- **Конец:** теги снимаются, мобы в радиусе 48 блоков от игроков удаляются (без дропа), время возвращается игровым правилам.
- **Риски:** мобы спавнятся в 6–30 блоках от игрока без проверки на блоки — часть может появиться в стене и задохнуться. Нагрузка: 3 моба × (20 мин / 25 с) = ~144 сущности за ивент, самые тяжёлые тики среди всех ивентов (поиск и спавн каждые 25 с).

### 3.3 Царь горы (`koth`)

- **Механика:** зона радиусом 7 блоков в 200–900 блоках от центра. Прогресс растёт на 1/60 в секунду, только если внутри ровно один игрок; при двух и более — «оспорено», прогресс заморожен; при пустой зоне — падает на 0.6/60 в секунду. Победа — 100 % при условии ≥ 20 секунд внутри зоны.
- **Анти-эксплойт:** порог времени в зоне отсекает «прилетел на элитре на секунду»; награда одна на игрока; учитываются только игроки в оверворлде.
- **Конец:** по таймауту — без награды; при ручной отмене — без награды; при восстановлении после падения — награда держателю при прогрессе ≥ 50 %.
- **Риски:** центр выбирается по `getTopmostBlock()`, возможна зона на дереве или в воде. Прогресс привязан к тикам, а не к физическому времени — при сильных лагах чуть замедляется.

### 3.4 Босс-рейд (`bossraid`)

- **Механика:** в 40 блоках от случайного игрока спавнится `swipecraft:war_boss` (своя сущность:
  HP 520, теги `sw:boss`/`sw:event`) с титром, звуком
  спавна и частицей ауры. Урон каждого игрока пишется в `active.data.damage`, время рядом с боссом
  (≤ `nearRadius`) — в `participation`.
- **Фазы** на 66 % и 33 % HP (`phaseThresholds`): по порогу отправляется
  `event entity @e[tag=sw:boss,limit=4] swipecraft:phase_2|phase_3` — смена скорости/урона и
  призыв 3 миньонов (`minions`), плюс усиление босса. Через скрипт компоненты поведения менять
  нельзя (`EntityAttributeComponent`/`minecraft:behavior.*` — только чтение), поэтому фазы живут
  в `events`+`component_groups` entity JSON, а скрипт лишь дёргает событие.
- **Fallback:** если кастомная сущность не подхвачена (игрок без ресурспака, кривой пак),
  спавнится `minecraft:ravager` с `health_boost` XV (+60 HP) и `resistance` II —
  эффективно ≈320 HP, фазы в этом режиме дают только эффекты и миньонов.
  режим спавна пишется в `active.data.kind`, а у fallback-босса он ещё и виден в nameTag
  («Владыка анархии (fallback)») — чтобы админ на живом сервере сразу понял, что пак не подхвачен.
- **Награда:** доля урона ≥ 5 % и ≥ 20 секунд участия. Последний удар сам по себе награду не даёт.
- **Конец:** при смерти босса — выплата сразу; при таймауте или пропаже (выгрузка чанка) — выплата по записанному урону; при падении сервера — то же; офлайн-участники получают награду при входе.

### 3.5 Двойной лут (`doubleloot`)

- **Механика:** 45 % шанс дополнительного ресурса при разрушении руды (таблица `blockBonus`, 16 видов) + 2× опыт за блок; 40 % шанс бутылочки опыта с мобов + 2× опыт.
- **Конфиг:** `EVENTS.doubleloot` — длительность 60 мин, `breakChance`, `mobChance`, `blockBonus`.
- **Конец:** сводка «бонусных предметов за ивент».
- **Риски:** бонус выдаётся напрямую в инвентарь (не через дроп), поэтому работает и с `doTileDrops=true`. Учитываются только блоки из списка — кастомные руды этапа 5 нужно добавить в конфиг. Ивент не пишет данные каждый тик — самый дешёвый по нагрузке.

### 3.6 Охота за головами (`bountyhunt`)

- **Механика:** цель — игрок с максимальным числом убийств (не меньше 1), при равенстве — случайный. Цель светится (`glowing`, обновление каждые 20 с) и получает уведомление. Убийство цели даёт лут, после чего выбирается новая цель (исключая убийцу и жертву).
- **Конец:** эффект снимается, цель больше не видна сквозь стены.
- **Риски:** `glowing` в Bedrock виден сквозь стены только на близкой дистанции и зависит от настроек клиента; на мобильных с низким render distance подсветка почти не помогает — это известное ограничение движка.

### 3.7 Lifesteal-час (`lifesteal`)

- **Механика:** у каждого игрока счётчик сердец (0…6). Убийство +1, смерть −1, разница сразу применяется эффектом `health_boost` (amplifier = уровень − 1, то есть +2 HP за сердце), эффект продлевается под длительность ивента каждые 20 секунд.
- **Конец:** `health_boost` снимается у всех, счётчики обнуляются.
- **Ограничение:** честного «минус сердце» (уменьшение максимума ниже 20 HP) в API 2.11.0 нет — `EntityAttributeComponent` не даёт опустить максимум ниже базового. Минусовые сердца дают только визуальный дебафф через `resistance`/`weakness` — в текущей версии не реализовано, чтобы не ломать баланс. Это «плюсовая» версия lifesteal: смерть отнимает накопленное, но не ниже базы.
- **Риски:** при выходе игрока эффект остаётся до истечения (максимум 5 минут) — на повторном входе обновляется.

## 5. Команды и админ-меню

```
/sw:event                  статус (то же, что status)
/sw:event status           активный ивент, следующий, история, отложенные награды
/sw:event next             сколько до следующего
/sw:event list             все 7 ивентов с id
/sw:event start <id>       ручной запуск (идёт вместо текущего)
/sw:event stop             остановить активный
```

Требуется `GameDirectors` + тег `admin`. То же доступно в форме: `/sw:admin` → «Ивенты» → кнопка на каждый ивент, «Остановить активный ивент». Ручной запуск пишется в аудит-лог (`event-start-manual`).

## 6. Локализация

Все тексты ивентов — в `src/events/messages.ts`, подключены через `addDict()` из `src/kernel/i18n.ts` (ru + en). Названия ивентов — ключи `ev.name.<id>`; шаблоны титров и чата используют `{name}`, `{player}`, `{minutes}` и т. п. Игрок с `lang=en` видит английские анонсы, с `lang=ru` — русские.

## 7. Производительность

| Ивент | Что делает каждый тик | Риск лага |
|---|---|---|
| `doubleloot` | ничего (только хуки `playerBreakBlock`/`entityDie`) | минимальный |
| `bloodmoon` | проверка таймера раз в секунду, спавн волны раз в 25 с | высокий: спавн 3 сущностей + 4 эффекта |
| `bossraid` | поиск босса, пересчёт участия по всем игрокам раз в секунду | средний: O(игроки) в секунду |
| `koth` | проверка игроков в радиусе раз в секунду | средний: O(игроки) в секунду |
| `bountyhunt` | обновление `glowing` раз в 20 с | низкий |
| `airdrop` | частицы столба 8 секунд, затем ничего | низкий |
| `lifesteal` | эффекты раз в 20 с | низкий |

Ни один ивент не выполняет тяжёлых циклов каждый тик: частицы — только первые 8 секунд аирдропа и раз в 15 секунд у босса, поиск сущностей — только по игрокам, без `getEntities()` без ограничения радиуса.

## 8. ПРОВЕРЕНО / РИСКИ

**Проверено на стабе (`/tmp/smoke2`, node-стаб движка + реальный бандл):**

- регистрация `/sw:event`, инициализация планировщика в `worldLoad`, 8 задач тикера;
- запуск и остановка всех 7 ивентов через команды, анонсы и титры во всех трёх ветках (5 мин, 1 мин, старт);
- аирдроп: столб частиц, приземление сундука с наполненным контейнером, координаты в чате;
- KOTH: начисление прогресса, «оспорено», победа на 100 %, выдача 2 алмазных блоков + 3 роллов в инвентарь;
- босс-рейд: спавн с тегом, учёт урона, выплата трём участникам по долям (55/36/9 %), отказ при недостатке участия;
- кровавая луна: `setTimeOfDay(18000)`, волна мобов с тегом, бонусный лут;
- охота: выбор цели по убийствам, выдача награды, перевыбор цели;
- lifesteal: `health_boost` на убийце, снятие при финише;
- двойной лут: бонус за руду, опыт через `spawnXp`;
- персистентность: сохранение активного ивента, продолжение после «рестарта», восстановление просроченного KOTH с наградой, отложенная награда и её выдача при входе игрока.

**Не проверено на живом клиенте (только стаб):** валидность ID частиц (`minecraft:endrod`), слышимость звуков (`mob.wither.spawn`, `random.anvil_land`, `random.levelup`, `random.orb`, `ambient.cave`), видимость титров на мобильных, реальный эффект `health_boost` на HP, поведение `glowing` в Bedrock, фактическая наполняемость сундука при `BlockInventoryComponent.container === undefined`.

**Честные ограничения:**

- «Босс» — равен 320 HP за счёт эффектов; максимум HP и масштаб из скрипта не меняются.
- Lifesteal только добавляет сердца, не отнимает ниже базовых 20 HP.
- Мобы кровавой луны спавнятся без проверки коллизий.
- Кровавая луна меняет время мира: если у вас включён `doDaylightCycle`, ивент перекрывает его на 20 минут.
- Ивенты не используют чат-хуки и не блокируют команды — в 2.11.0 таких API нет.
