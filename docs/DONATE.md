# Донат Swipecraft (этап 6)

## 0. Честная рамка

На Bedrock Dedicated Server нет API приёма платежей. Поэтому донат устроен как
«игрок подаёт заявку → админ проверяет платёж вне игры → одобрение включает перки»:

- скрипт никогда не начисляет тариф сам и не списывает деньги;
- `submitRequest` только регистрирует заявку и зовёт админов;
- все бонусы включаются ровно в момент `decideRequest(approve)` (или ручной `applyTier`);
- возврата в скрипте нет: `DONATIONS.refundAllowed = false`, откат возможен только отзывом
  тарифа (`revokeTier`) либо спора (`markDispute`);
- за реальные деньги не продаются ₡, предметы, ключи к кейсам с предметами и любые
  преимущества в бою - см. `docs/MONETIZATION.md` и `docs/LEGAL.md`.

«Автоматический донат» на BDS - это дыра, через которую кто угодно выдал бы себе тариф
подменой ответа платёжки. Поэтому путь один: руки админа + журнал.

## 1. Тарифы

`DONATIONS.tiers` (цена в `DONATIONS.currency`, `priceMultiplierRub = 1`):

| Тариф | Цена | Дней | Приоритет входа | Префикс `nameTag` | Частицы | Подарок |
|---|---|---|---|---|---|---|
| `bronze` | 199 ₽ | 30 | да | `§7[§8бронза§7]§r ` | нет | 1 прокрутка/мес |
| `silver` | 399 ₽ | 30 | да | `§f[§7серебро§f]§r ` | да | 2 прокрутки/мес |
| `gold` | 799 ₽ | 30 | да | `§6[§eзолото§6]§r ` | да | 3 прокрутки/мес |

Подарок - это `cosmetics.rolls`: прокрутки **косметического** кейса (`COSMETIC_CASE`,
12 позиций `COSMETICS`, только trail/prefix/suffix/join). Полей `keysPerMonth` и
`casesPerMonth` в `DONATIONS` больше нет, `autoGrantKeys` удалён: донат не может выдать
ключ к кейсу с предметами. Проверено стабом («выдача не даёт ключей и монет»).

Длительность при выдаче: `minDays = 7` ... `maxDays = 120`. Продление суммируется:
`donorUntil = max(now, donorUntil) + days`.

## 2. Заявка и решение

```
/sw:don -> выбор тарифа -> поля "дней (7...120)" и "Discord / ID платежа" -> "Подать заявку"
   -> submitRequest(player, tier, days, note)
```

- у игрока может быть только одна открытая заявка: повтор отклоняется с id первой
  (иначе спам в очереди = способ спрятать нормальную заявку);
- id заявки - base36 от времени + 2 символа соли, хранятся последние `requestsMax = 80`;
- заявка уходит в `sw:don:requests`, в аудит (`donate/request`) и всем онлайн-админам в чат:
  `[donate] заявка #id: Name -> tier на N дн. (комментарий)`;
- в комментарии игрок пишет идентификатор платежа - единственная связка «заявка <-> платёж»,
  `DONATIONS.requireNote = true` (пустая заметка = предупреждение админу в ответе выдачи);
- `decideRequest(actor, id, approve)`: повторное решение отклоняется («заявка уже обработана»),
  при одобрении - `applyTier` + уведомление игроку, если он онлайн; при отказе -
  статус `rejected`, `by = actor`, игроку `don.rejected`.

Ручные пути: `/sw:admin` -> «Мета» -> «Донат»: «Заявки - N», «Выдать вручную»,
«Отозвать привилегию», «Журнал выдач», «Цель сбора», «Спорный платёж»,
«Выдать косметику игроку», «Журнал приглашений», «Очередь входа», «Выпустить всех».
Все выдачи идут через `applyTier`, поэтому в журнале всегда указан `actor` - «выдал за
деньги» и «выдал просто так» различимы по `note`, а не по кнопке.

Регламент админа до нажатия «Одобрить»: сверить ID платежа из `note` с поступлением,
сверить ник, только потом одобрять. Нет платежа - «Отклонить», заявка не должна висеть.

## 3. Что именно включается

`applyTier(actor, playerId, playerName, tier, days, note)`:

1. блок по спору: если `donBlockUntil > now` - выдача отклоняется со строкой
   «выдача заблокирована: спорный платёж до ... (причина: ...)» + `notifyAdmins`;
2. `donorTier` / `donorUntil` + `markDirty` (работает и для офлайн-игроков: `getMeta`);
3. запись в `sw:don:grants` (последние 300): `t`, `actor`, `player`, `playerId`, `tier`,
   `days`, `note`;
4. аудит `donate/grant` (или `donate/revoke` при `none`);
5. `refreshNameTag` -> `applyIdentity` = префикс тарифа + экипированные prefix/suffix;
6. `addRaised(round(price * days / tier.days))` - прогресс цели сбора;
7. чек игрока: `addReceipt(..., via = "donate", сумма, actor)` в `sw:don:receipts`;
8. `autoGrantGiftById` - подарочные прокрутки за этот месяц (см. §4);
9. сообщение игроку `don.thanks` с датой окончания.

Прокси-поля не хранятся: `tierOf(player)` каждый раз сверяет `donorUntil` с часами, так что
истёкший тариф перестаёт работать мгновенно, даже если игрок не выходил из игры; при сбросе
в `none` префикс снимается в том же вызове.

## 4. Подарок вместо «ключей в месяц»

`autoGrantGift(player)` вызывается на спавне и из задачи `meta-unlock` (200 тиков):

- счётчик `sw:don:usage` - `{ month, gifts, noticeAt }` на игрока, месяц календарный UTC;
- пока `month` совпадает с текущим - повторной выдачи нет, сколько бы раз задача ни прошла;
- сумма = `DONATIONS.tiers[tier].giftRolls` (1 / 2 / 3);
- если игрок офлайн, прокрутки всё равно начисляются в его кошелёк
  (`meta.cosmetics.rolls`) - «не зашёл в месяце» не означает «потерял»;
- трата - в `/sw:shop`: «Открыть подарком (N)» без списания ₡;
- в аудит уходит `donate/gift` с `+N прокруток косметики (tier)`.

## 5. Косметика и идентичность

- `nameTag` = `донорный префикс + экипированный prefix + ник + экипированный suffix + §r`
  (`identityName`), обновляется на спавне, при выдаче/отзыве тарифа, при покупке и экипировке;
- трейл: `swipecraft:donor_trail` для тарифов с `particles: true` (silver, gold); если
  игрок экипировал свою частицу (`COSMETICS`, kind `trail`) - показывается она, то есть
  «след» можно получить и без денег, за ₡;
- кастомная частица может не загрузиться (игрок без ресурспака) - фолбэк
  `minecraft:basic_smoke_particle`; ошибка на одном игроке не останавливает обход
  остальных (`spawnTrail` + `trailSweep`, `DONATIONS.trailEveryTicks = 10`);
- сообщение о входе - экипированный `join`-шаблон (`announceJoin`), `{name}` подставляется;
- ни лута, ни статов, ни скорости копа косметика не даёт - она только в `nameTag` и частицах.

## 6. Возвраты, споры и защита от мошенничества

- в скрипте нет «вернуть деньги»: `refundAllowed = false`. Откат - только отзыв тарифа;
- «Спорный платёж» -> `markDispute(actor, target, reason)`: снимает тариф (`applyTier none`)
  и ставит `donBlockUntil = now + disputeBlockDays (30)`, `donBlockReason = reason`;
- с этим флагом блокируются все выдачи, включая ручные и из одобрения заявки;
- спорящие видны: `disputeLines()` в админке и в `sw:meta info`;
- закрытие спора - тот же экран, toggle «Спор закрыт» -> `clearDispute`;
- выдача без комментария при `requireNote` возвращает админу предупреждение - «забыл ID
  платежа» видно сразу;
- ₡-эмиссия не обходится: возврат за дубликат косметики идёт через `refundBurn` (уменьшает
  `ledger.burned`, упирается в `CURRENCY.maxBalance`), а не через `mint`;
- донат-путь не вызывает `mint`/`grantKeys` вообще - это ровно то, что проверяет стаб.

## 7. История покупок игрока

`sw:don:receipts` (последние 120), игрок смотрит сам: `/sw:don` -> «Мои покупки и получения»
или `/sw:shop` -> «Мои покупки и получения». Типы (`via`): `donate` (за реальные деньги),
`coins` (покупка за ₡), `roll` (из подарка), `gift` (выдача/цель сбора), `refund` (возврат
за дубликат). Это выполненное требование правил Mojang: пользователю, отдавшему реальные
деньги, доступна онлайн-история покупок - без участия админа.

## 8. Цель сбора (server-wide reward)

`DONATIONS.goal`: `rewardCoins = 1200`, `rewardKeys = 1`, `ttlDays = 14`.

- «Цель сбора» -> «Назначить цель сбора» (`setGoal`): название (до 60 симв.), сумма, срок;
- прогресс растёт из выдач (`addRaised`), снимается цель - «Снять цель»;
- при `raised >= target` - `goalPayout()` ровно один раз (`paidAt`): всем из реестра
  балансов 1200 ₡ (`mintToId`, в т.ч. офлайнам) + 1 ключ (онлайн - `grantKeys`, офлайн -
  `meta.caseKeys`), чек `via = "gift"`, `world.sendMessage`, аудит `donate/goal-payout`,
  `notifyAdmins`;
- награда одинаковая для всех - это тот формат, который правила Mojang разрешают явно.

Проверено стабом: «цель сбора: ручная выдача добирает её и платит всем».

## 9. Приоритетный вход

Очередь нужна не «для красоты», а чтобы на переполненном сервере донер попал в игру, а не
ловил таймаут подключения:

- тюнинги: `queueEnabled`, `queueSoftCap` (82), `queueReleaseAt` (74) - гистерезис, чтобы не
  дёргать игроков на флуктуациях онлайна; меняются на ходу (`/sw:meta set ...`);
- при входе, если онлайн выше `queueSoftCap` и игрок не донер - точка `QUEUE.waitSpot`
  (6, 81, 6), тег `sw:queued`, action-bar раз в `QUEUE.noticeEveryTicks` (40 тиков);
- как только онлайн упал до `queueReleaseAt` - игрок отпускается сам, теги снимаются;
- донер проходит мимо очереди (`isPriorityPlayer`), и если тариф выдали во время ожидания -
  он отпускается на следующем тике, переоформлять заявку не нужно;
- на телепорт в зал ожидания даётся grace в античит (иначе «телепортировался сам»);
- админ: «Очередь входа» (состав) и «Выпустить всех» (`releaseAll`).

Очередь не кикает и не держит игрока в аду: он в мире, в безопасной точке, и выходит из
очереди в течение секунды после освобождения слота.

## 10. Хранилище

| Ключ | Что | Лимит |
|---|---|---|
| `sw:don:requests` | заявки, все статусы | 80 последних |
| `sw:don:grants` | журнал выдач/отзывов (с `actor`) | 300 последних |
| `sw:don:receipts` | чеки игрока: donate/coins/roll/gift/refund | 120 последних |
| `sw:don:usage` | `{month, gifts, noticeAt}` - счётчик подарков | по игроку |
| `sw:don:goal` | цель сбора: label, target, raised, deadline, paidAt | одна |
| `sw:ref:codes` | реестр кодов приглашений | 5000 |
| `sw:ref:log` | bind/reward/reject/reset | 200 последних |

Всё через `saveWorldJson` (чанки + debounce), как и остальной мета-слой. Спор
(`donBlockUntil`, `donBlockReason`) живёт в кошельке игрока (`sw:eco:meta`), а не в
отдельном ключе: его нельзя «потерять вместе с журналом».

## 11. Что проверяет стаб-харнесс

`npm run stability`, группы `donations`, `referrals`, `economy`:

- заявка уходит админу и сохраняется; дубликат открытой заявки отклоняется;
- одобрение выдаёт тариф, префикс и запись в журнал;
- выдача другому игроку не даёт ни ключей, ни ₡, а только подарочные прокрутки;
- спорный платёж снимает тариф, ставит блок 30 дней с причиной и снимается `clearDispute`;
- цель сбора: ручная выдача добирает цель, платит всем (онлайн и офлайн), оставляет чеки,
  админ может снять цель;
- косметика покупается за ₡ и меняет `nameTag`; подарочная прокрутка не выдаёт предметов в
  инвентарь и не тратит ₡; чек покупки виден игроку;
- рефералка: код стабилен, самосвязь и чужой код отклоняются, окно 72 ч держит старого
  игрока, награда ждёт 2 часа игры и упирается в дневной лимит;
- словари ru и en синхронны (важно для `don.rules.1` и `rules.text`).

ТРЕБУЕТ ЖИВОГО ТЕСТА (в песочнице это не проверить): отображение `§7[§8бронза§7]§r` на
телефоне, частицы `swipecraft:donor_trail` / `trail_ember|frost|soul` на мобильных,
`join`-сообщение, реальное поведение очереди под нагрузкой, и сами покупки - их в игре
соверждает человек.
