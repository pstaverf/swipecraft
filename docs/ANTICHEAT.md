# Античит Swipecraft (этап 3)

## Модель работы

Античит **ничего не блокирует и никого не наказывает**. Он:

1. считает скор по весам детектов,
2. пишет каждое срабатывание в аудит-лог (in-memory + dynamic property),
3. пишет онлайн-админам сообщение при переходе порога,
4. отдаёт скор в админ-меню для **ручного** решения (кик / бан / заморозка).

Скор затухает (`decayPerMinute`), поэтому разовые аномалии не накапливаются. Все решения принимает человек.

## Окна допуска (что защищает от ложных срабатываний на мобильных)

| Событие | Допуск |
|---|---|
| Вход в мир | 3000 мс |
| Респавн | 3000 мс |
| Любой урон по игроку (knockback) | 1200 мс |
| Телепорт `/rtp` | 4000 мс |
| Телепорт границей / лобби | 2000–2500 мс |
| Смена измерения | 1500 мс |
| Нахождение в лобби | 1500–2000 мс (обновляется постоянно) |
| Пауза сэмплинга > 1200 мс (лаг-спайк) | сэмпл отбрасывается |
| Платформа `Mobile` (`clientSystemInfo.platformType`) | +бонус допуска в конфиге детекта |

Накопление вместо реакции на одиночное срабатывание: каждый детект требует `hits` срабатываний внутри `windowMs`. Одиночный выброс = ноль последствий.

## Надёжность детектов в рамках Script API 2.11.0

| Детект | Надёжность | Что видит | Основные источники ложных срабатываний |
|---|---|---|---|
| `reach` | **приблизительный** | расстояние между позициями атакующего и жертвы на момент события | лаг 150–300 мс даёт расхождение позиций, knockback, езда, вода; у снарядов/стрел не считается |
| `attackRate` (авто-клик) | **надёжный при выборке ≥15 ударов** | интервалы между ударами, СКО < 15 мс | ручной спам с одинаковым ритмом теоретически возможен, но требует усилий |
| `speed` | **приблизительный** | горизонтальная скорость по сэмплам (200 мс+) | эффекты, лёд, лодка, элитра, лошадь, отброс, лаг-спайк; все фильтруются |
| `fly` | **приблизительный** | отсутствие блока под ногами при вертикальной скорости ≈ 0 | лианы, вода, jump boost, slow falling, лестницы, лаг |
| `nuke` | **приблизительный** | частота разрушения блоков | эффективная кирка + haste, стройка в креативе (у нас нет), лаг |
| `placeRate` | **приблизительный** | частота установки блоков | мосты, заливка лавы/воды, стройка |
| `containerSpam` | **надёжный** | частота открытия контейнеров | двойные сундуки, автосортировка вручную |
| `entitySpam` | **приблизительный** | частота дропа предметов игроком | разгрузка инвентаря после рейда |
| `stackAnomaly` | **надёжный факт** | `amount > maxStackAmount` или `amount <= 0` | кастомные предметы с max_stack > 64 (настраивается) |
| X-ray | **невозможно** | невидим серверу: рендер клиента | — |
| Killaura (поворот головы) | **невозможно напрямую** | событие удара не содержит rotation | частично закрыто `player-movement-action-direction-threshold=0.85` в server.properties |
| Переполнение пакетов | **невозможно** | Script API не видит пакеты | — |
| Скорость через снаряды/жёмчуг | не покрыто | — | — |

Что дополнительно закрывает сам движок (этап 2, `server.properties`):

- `server-authoritative-entity-attack-range-validation=enforce` + `tolerance=1.0` — движок сам отклоняет удары вне дистанции;
- `server-authoritative-entity-attack-request-validation=enforce` — тип атаки должен соответствовать предмету;
- `player-movement-action-direction-threshold=0.85` — удар должен совпадать с направлением взгляда;
- `server-authoritative-block-breaking-pick-range-scalar=1.5` — дистанция ломания.

## Конфиг и горячая правка (без перезапуска)

Конфиг лежит в dynamic property `sw:ac:cfg`, дефолты — в `src/security/anticheat/config.ts`. Изменения применяются мгновенно.

```
/sw:ac show                                  — текущие пороги и веса
/sw:ac set threshold 80                      — порог тревоги
/sw:ac set decayPerMinute 3                  — затухание
/sw:ac set alertCooldownMs 180000            — пауза между тревогами
/sw:ac set detectors.reach.weight 15
/sw:ac set detectors.reach.hits 4
/sw:ac set detectors.reach.tolerance 1.5     — допуск в блоках
/sw:ac set detectors.speed.enabled false
/sw:ac set limits.maxTntPerArea 16
/sw:ac reset                                 — вернуть дефолт
```

То же самое доступно в админ-меню (мобильный путь): `/sw:menu` → «Админ-панель» → «Настройки античита».

Значения по умолчанию:

| Параметр | Значение |
|---|---|
| threshold | 60 |
| decayPerMinute | 2 |
| alertCooldownMs | 300000 |
| reach | weight 12, hits 3, window 6000 мс, tolerance 1.2, mobile +1.2 |
| attackRate | weight 6, hits 12, window 4000 мс |
| speed | weight 10, hits 4, window 5000 мс, tolerance 1.4, mobile +0.6 |
| fly | weight 12, hits 4, window 8000 мс |
| nuke | weight 10, лимит 20 блоков / 4000 мс |
| placeRate | weight 6, лимит 20 блоков / 3000 мс |
| containerSpam | weight 4, лимит 20 / 5000 мс |
| entitySpam | weight 4, лимит 25 / 5000 мс |
| stackAnomaly | weight 25, maxStackAmount 64 |

## Ручные санкции

`/sw:menu` → «Админ-панель» → «Санкции»:

- **Кик** — `kick @s <reason>` от имени игрока; если команда недоступна (allow-cheats=false), выполняется `Entity.remove()` (см. «РИСКИ» этапа).
- **Бан** — флаг в профиле игрока + немедленный кик; при следующем входе игрок выкидывается на спавне. Срок: бессрочно или до timestamp.
- **Заморозка** — `inputPermissions` выключает движение и камеру (для разбора ситуации).
- **Разбан** — снятие флага.

Все действия пишутся в аудит с именем админа.

## Переменные окружения мобильного клиента

`player.clientSystemInfo` даёт `platformType` (`Mobile`/`Desktop`/`Console`), `maxRenderDistance`, `locale`. Используется для бонуса допуска и для `stats.mobile`. Пинг клиента API не отдаёт — поэтому «учёт пинга» реализован через окна допуска и фильтр лаг-спайков, а не через реальное значение пинга.
