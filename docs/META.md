# Мета-слой Swipecraft (этап 5–6)

Слой отвечает за всё, что игрок «копит»: монеты, кланы, кейсы, рынок, квесты, донат, косметику
и приглашения.
Он надстраивается над ядром (`src/kernel`) и не имеет права ронять сервер: каждый шаг
оборачивается в `safeStep`, а любое хранилище проверяется на размер до записи.

## 1. Как слой включается

`src/bootstrap/world-load.ts` → `boot()`:

```
initAudit → applyWorldRules → initSeason → initBorder → initSpawn → initLimits
→ initAntiDupe → initAnticheat → initMeta() → initEvents()
```

`initMeta()` (`src/meta/index.ts`) делает три вещи:

1. загружает состояния (`loadBalances`, `initEconomy`, `loadMarket`, `loadCases`,
   `loadClans`, `loadProgress`, `loadDonations`, `loadCosmetics`, `loadReferrals`);
2. подписывается на `world.afterEvents`: `playerSpawn` (подарок донера за месяц,
   регистрация реферального кода, `nameTag` (тариф + экипированная косметика),
   кастомное сообщение захода, строка топ-листа, тег клана, возврат просроченных лотов,
   постановка в очередь входа), `playerLeave` (снятие с очереди + сохранение),
   `entityDie` (PvP-учёт, серии, войны кланов, lifesteal), `playerBreakBlock` (квест по руде);
3. регистрирует фоновые задачи в планировщике ядра.

| Задача | Интервал, тиков | Бюджет, мс | Что делает |
|---|---|---|---|
| `meta-unlock` | 200 | 4 | разблокировка замороженных монет, подарок донера (прокрутки косметики) |
| `meta-flush` | 600 | 20 | сохранение всех документов слоя на диск |
| `meta-market` | 200 | 6 | sweep просроченных лотов, возврат предметов |
| `meta-clans` | 1200 | 14 | итоговка войн, чистка неактивных, синк составов |
| `meta-donor` | 10 | 3 | частицы-трейл донерам |
| `meta-queue` | 20 | 3 | очередь входа: держим в зоне ожидания, отпускаем при свободе |
| `meta-streaks` | 600 | 3 | сгорание серий PvP |
| `meta-leaderboard` | 1200 | 6 | сброс топ-листа |
| `meta-ref` | 600 | 4 | `rewardSweep`: награды за приглашения (нужно 2 ч игры новичка) |
| `meta-prune` | 21600 | 6 | `pruneBalances`: чистка пустых кошельков неактивных игроков (60 дней) |

Ни одна задача не работает каждый тик; самая частая (`meta-donor`) делает 3 мс работы
на 0,5 с и только пока в мире есть донеры.

## 2. Хранилище

Все данные лежат в dynamic properties мира как целый JSON, который `src/kernel/store.ts`
режет на чанки по `CONFIG.store.chunkSize` (7000 байт) — потому что одно строковое
свойство ограничено 32767 байтами.

| Ключ | Содержимое |
|---|---|
| `sw:eco:cfg` | экономические тюнинги (комиссии, лимиты, очередь) |
| `sw:eco:meta` | кошельки и прогресс игроков, `Record<playerId, PlayerMeta>` |
| `sw:eco:ledger` | реестр эмиссии: `minted`, `burned`, `fees`, `accounts`, `mintToday` |
| `sw:eco:tx` | последние транзакции (для аудита) |
| `sw:market` | лоты рынка игроков (до 400 КБ) |
| `sw:cases:log`, `sw:cases:stats` | журнал вскрытий и агрегаты |
| `sw:clans:index` | индекс: `clanIds`, `byPlayer`, `names`, `totalBytes` |
| `sw:clan:<id>` | один документ клана (до 6000 байт) |
| `sw:meta:top` | топ-лист (60 строк) |
| `sw:don:requests`, `sw:don:grants`, `sw:don:usage` | заявки, журнал выдач, счётчики подарков |
| `sw:don:receipts` | чеки игрока: donate / coins / roll / gift / refund (120) |
| `sw:don:goal` | цель сбора: label, target, raised, deadline, paidAt |
| — | косметика отдельного ключа не имеет: `owned/rolls/equipped` живут в кошельке игрока (`sw:eco:meta`) |
| `sw:ref:codes`, `sw:ref:log` | реестр кодов приглашений (5000) и журнал bind/reward/reject/reset (200) |

Правила, которые закрывают главную болевую точку Bedrock-аддонов:

- запись выполняется только после проверки размера (`budgetOk`);
- при переполнении мир `getDynamicPropertyTotalByteCount()` превышает квоту — запись
  отклоняется, админы получают алерт, данные остаются в памяти и в следующий
  успешный цикл доезжают на диск; ничего не «тихо теряется»;
- деньги и прогресс не хранятся в профиле игрока — у профиля своя квота и свои
  задачи, смешивать их нельзя.

## 3. UI и команды

Все действия — только через формы (`@minecraft/server-ui`), чат для действий не
используется (в Script API нет события чата).

| Команда | Кто | Открывает |
|---|---|---|
| `/sw:menu` | все | главное меню (кошелёк, рынок, кейсы, клан, квесты, донат, косметика, приглашения, RTP, правила, статистика, язык) |
| `/sw:eco` | все | кошелёк, перевод, продажа предмета, топы, квесты |
| `/sw:market` | все | рынок: просмотр, покупка, продажа, мои лоты, поиск |
| `/sw:case` | все | кейсы: честные шансы, вскрытие за монеты и за ключи |
| `/sw:clan` | все | клан: состав, права, доска, дом, казна, войны, топ |
| `/sw:quest` | все | ежедневная награда и квесты |
| `/sw:don` | все | каталог доната, заявка, «Мои покупки и получения» |
| `/sw:shop` | все | косметика: каталог, покупка за ₡, экипировка, подарочные прокрутки |
| `/sw:ref` | все | приглашения: мой код и ввод кода |
| `/sw:admin` | admin | админ-панель, вкладка «Мета» |
| `/sw:meta` | admin | `status`, `info`, `tx`, `flush`, `set <параметр> <число>`, `reset` |
| `/sw:event` | admin | `status`, `next`, `list`, `start <id>`, `stop` |

Админ-вкладка «Мета»: состояние слоёв, экономика (параметры, начислить/списать,
журнал транзакций, счета и эскроу, сброс конфига), кланы (хранилище, чистка
неактивных, принудительный роспуск), рынок (модерация лотов), кейсы (агрегаты и
журнал), донат (заявки, ручная выдача, отзыв, журнал, цель сбора, спорный платёж,
выдача косметики, журнал приглашений, очередь входа).

## 4. Языки

Все строки идут через `t(player, key, params)` (`src/kernel/i18n`). Словари слоя
подключаются импортом `./messages` из каждого модуля (`src/meta/messages.ts`,
`src/ui/messages.ts`), поэтому ключи регистрируются один раз при старте и не
раздувают бандл дубликатами. Синхронность ключей ru/en проверяется стабом
(«словари ru и en синхронны») — иначе `don.rules.1` и `rules.text` уехали бы в одну локаль.
Переключение языка — в `/sw:menu` (сохраняется в профиле). Языковые имена сущности и
пака — `packs/resource_pack/texts/{ru_RU,en_US}.lang`.

## 5. Монетизация и приглашения в этом слое

- донат (`donations.ts`): три тарифа, выдача только руками (`applyTier`), чеки
  (`sw:don:receipts`), цель сбора и споры; за деньги не продаются ₡, предметы и
  ключи к `basic`/`elite` — см. `docs/MONETIZATION.md`;
- косметика (`cosmetics.ts`): 12 позиций, 4 слота (`trail`/`prefix`/`suffix`/`join`),
  покупка только за ₡ (`COSMETIC_CASE` — 3500 ₡), возврат за дубликат через `refundBurn`
  (не через `mint`), `nameTag` = `identityName` (префикс тарифа + prefix + ник + suffix);
- приглашения (`referrals.ts`): код 6 знаков из `player.id` (детерминированно), привязка
  один раз в первые 72 ч, награда обоим только после 2 ч наигранного времени,
  лимиты 3/сутки и 15 000 ₡/месяц, журнал `sw:ref:log`;
- всё это видно в `sw:meta status` (строки `донат:` и `приглашения:`) и в `sw:meta info`
  (там же `disputeLines` и журнал рефералки).

## 6. Что требует проверки живым сервером

- фактическая запись big JSON в dynamic properties на BDS 1.26.60 (объём, фрагментация
  ключей, поведение после `restart`);
- отображение кастомной модели босса и частиц на мобильных клиентах (iOS/Android);
- `sound_definitions` из пользовательского ресурспака на телефоне;
- удобство форм на маленьком экране (выпадающие списки длиннее 10 пунктов);
- `nameTag` с §-кодами (`§7[§8бронза§7]§r `) и постфиксом: префикс ставится в
  `applyIdentity`, но как он обрезается в списке игроков и на таб-доске — только живой тест;
- частицы `swipecraft:donor_trail`, `trail_ember`, `trail_frost`, `trail_soul`
  (PNG генерирует `tools/gen-textures.mjs`): виден ли трейл на телефоне и режет ли FPS;
- кастомное сообщение захода (`join`-косметика) уходит в `world.sendMessage` — под боем
  его можно не заметить;
- форма каталога косметики (12 позиций + снятие слотов + журнал): влезает ли в экран.

Логику этих мест стаб-харнесс (`npm run stability`) проверяет, но «красиво/не красиво
на телефоне» он проверить не может.
