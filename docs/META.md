# Мета-слой Swipecraft (этап 5–6)

Слой отвечает за всё, что игрок «копит»: монеты, кланы, кейсы, рынок, квесты, донат, косметику
и приглашения.
Он надстраивается над ядром (`src/kernel`) и не имеет права ронять сервер: каждый шаг
оборачивается в `safeStep`, а любое хранилище проверяется на размер до записи.

## 1. Как слой включается

`src/bootstrap/world-load.ts` → `boot()`:

```
initAudit → applyWorldRules → initSeason → initBorder → initSpawn → initLimits
→ initAntiDupe → initAnticheat → initMeta() → initEvents()
```

`initMeta()` (`src/meta/index.ts`) делает три вещи:

1. загружает состояния (`loadBalances`, `initEconomy`, `loadMarket`, `loadCases`,
   `loadClans`, `loadProgress`, `loadDonations`, `loadCosmetics`, `loadReferrals`);
2. подписывается на `world.afterEvents`: `playerSpawn` (подарок донера за месяц,
   регистрация реферального кода, `nameTag` (тариф + экипированная косметика),
   кастомное сообщение захода, строка топ-листа, тег клана, возврат просроченных лотов,
   постановка в очередь входа), `playerLeave` (снятие с очереди + сохранение),
   `entityDie` (PvP-учёт, серии, войны кланов, lifesteal), `playerBreakBlock` (квест по руде);
3. регистрирует фоновые задачи в планировщике ядра.

| Задача | Интервал, тиков | Бюджет, мс | Что делает |
|---|---|---|---|
| `meta-unlock` | 200 | 4 | разблокировка замороженных монет, подарок донера (прокрутки косметики) |
| `meta-flush` | 600 | 20 | сохранение всех документов слоя на диск |
| `meta-market` | 200 | 6 | sweep просроченных лотов, возврат предметов |
| `meta-clans` | 1200 | 14 | итоговка войн, чистка неактивных, синк составов |
| `meta-donor` | 10 | 3 | частицы-трейл донерам |
| `meta-queue` | 20 | 3 | очередь входа: держим в зоне ожидания, отпускаем при свободе |
| `meta-streaks` | 600 | 3 | сгорание серий PvP |
| `meta-leaderboard` | 1200 | 6 | сброс топ-листа |
| `meta-ref` | 600 | 4 | `rewardSweep`: награды за приглашения (нужно 2 ч игры новичка) |
| `meta-prune` | 21600 | 6 | `pruneBalances`: чистка пустых кошельков неактивных игроков (60 дней) |

Ни одна задача не работает каждый тик; самая частая (`meta-donor`) делает 3 мс работы
на 0,5 с и только пока в мире есть донеры.

## 2. Хранилище

Все данные лежат в dynamic properties мира как целый JSON, который `src/kernel/store.ts`
режет на чанки по `CONFIG.store.chunkSize` (7000 байт) — потому что одно строковое
свойство ограничено 32767 байтами.

| Ключ | Содержимое |
|---|---|
| `sw:eco:cfg` | экономические тюнинги (комиссии, лимиты, очередь) |
| `sw:eco:meta` | кошельки и прогресс игроков, `Record<playerId, PlayerMeta>` |
| `sw:eco:ledger` | реестр эмиссии: `minted`, `burned`, `fees`, `accounts`, `mintToday` |
| `sw:eco:tx` | последние транзакции (для аудита) |
| `sw:market` | лоты рынка игроков (до 400 КБ) |
| `sw:cases:log`, `sw:cases:stats` | журнал вскрытий и агрегаты |
| `sw:clans:index` | индекс: `clanIds`, `byPlayer`, `names`, `totalBytes` |
| `sw:clan:<id>` | один документ клана (до 6000 байт) |
| `sw:meta:top` | топ-лист (60 строк) |
| `sw:don:requests`, `sw:don:grants`, `sw:don:usage` | заявки, журнал выдач, счётчики подарков |
| `sw:don:receipts` | чеки игрока: donate / coins / roll / gift / refund (120) |
| `sw:don:goal` | цель сбора: label, target, raised, deadline, paidAt |
| — | косметика отдельного ключа не имеет: `owned/rolls/equipped` живут в кошельке игрока (`sw:eco:meta`) |
| `sw:ref:codes`, `sw:ref:log` | реестр кодов приглашений (5000) и журнал bind/reward/reject/reset (200) |

Правила, которые закрывают главную болевую точку Bedrock-аддонов:

- запись выполняется только после проверки размера (`budgetOk`);
- при переполнении мир `getDynamicPropertyTotalByteCount()` превышает квоту — запись
  отклоняется, админы получают алерт, данные остаются в памяти и в следующий
  успешный цикл доезжают на диск; ничего не «тихо теряется»;
- деньги и прогресс не хранятся в профиле игрока — у профиля своя квота и свои
  задачи, смешивать их нельзя.

## 3. UI и команды

Все действия — только через формы (`@minecraft/server-ui`), чат для действий не
используется (в Script API нет события чата).

| Команда | Кто | Открывает |
|---|---|---|
| `/sw:menu` | все | главное меню (кошелёк, рынок, кейсы, клан, квесты, донат, косметика, приглашения, RTP, правила, статистика, язык) |
| `/sw:eco` | все | кошелёк, перевод, продажа предмета, топы, квесты |
| `/sw:market` | все | рынок: просмотр, покупка, продажа, мои лоты, поиск |
| `/sw:case` | все | кейсы: честные шансы, вскрытие за монеты и за ключи |
| `/sw:clan` | все | клан: состав, права, доска, дом, казна, войны, топ |
| `/sw:quest` | все | ежедневная награда и квесты |
| `/sw:don` | все | каталог доната, заявка, «Мои покупки и получения» |
| `/sw:shop` | все | косметика: каталог, покупка за ₡, экипировка, подарочные прокрутки |
| `/sw:ref` | все | приглашения: мой код и ввод кода |
| `/sw:rank` | все | `info` — лестница и моё место, `roll [n]` — кейс рангов, `give <id>` — выдача (только admin) |
| `/sw:hud` | все | `on`/`off` — личная строка статуса, `status`, `rows`, `sidebar` — что реально ушло в сайдбар |
| `/sw:admin` | admin | админ-панель, вкладка «Мета» |
| `/sw:meta` | admin | `status`, `info`, `tx`, `flush`, `set <параметр> <число>`, `reset` |
| `/sw:event` | admin | `status`, `next`, `list`, `start <id>`, `stop` |

Админ-вкладка «Мета»: состояние слоёв, экономика (параметры, начислить/списать,
журнал транзакций, счета и эскроу, сброс конфига), кланы (хранилище, чистка
неактивных, принудительный роспуск), рынок (модерация лотов), кейсы (агрегаты и
журнал), донат (заявки, ручная выдача, отзыв, журнал, цель сбора, спорный платёж,
выдача косметики, журнал приглашений, сброс привязки приглашения, очередь входа).

### Тюнинги (`sw:eco:cfg`)

Двадцать одно значение `EcoTunables` (13 чисел и 8 булевых рубильников) лежат одним JSON в `sw:eco:cfg` и читаются на ходу:
комиссии и лимиты (`transferFeePercent` 4, `marketCommissionPercent` 7, `mintCapPerDay`
9000, `maxTransferPerTx` 150 000, `maxReceivePerDay` 400 000, `maxPerPairPerDay` 250 000),
допуски (`minPlaySecondsForTransfers` 1800, `minAccountAgeHours` 24) и пределы систем
(`clanMaxMembers` 24, `marketTtlDays` 14, `casePricePercent` 100). Отдельно — рубильники
очереди, cosmetics и модов мира:

| Ключ | По умолчанию | Что гасит |
|---|---|---|
| `queueEnabled` | `true` | очередь входа целиком (`queueOnSpawn` сразу отдаёт `false`) |
| `queueSoftCap` | `82` | порог, выше которого новых пускают через зал ожидания |
| `queueReleaseAt` | `74` | порог отпускания (гистерезис против дёрганья на флуктуациях) |
| `donorTrailsEnabled` | `true` | только партиклы трейлов: `spawnTrail` выходит `false` до проверки экипировки |
| `quarryEnabled` | `true` | авто-шахты: `quarryTick` выходит сразу, буферы и записи `sw:quarry` не трогаются |
| `totemsEnabled` | `true` | тотемы: обряд отказывает, `beforeEvents.entityHurt` не отменяется, реестр `sw:totems` и предметы не трогаются |
| `spawnProtectEnabled` | `true` | защиту спавна: ломку, установку, вёдра и взрывы на площади (см. `docs/WORLD-MODS.md` §2) |
| `ranksEnabled` | `true` | ранги: кейс закрывается, `rankTag` и префикс над головой снимаются, собранные ранги не теряются |
| `hudBarEnabled` | `true` | персональную строку статуса (action bar) |
| `hudSidebarEnabled` | `true` | общий сайдбар (`world.scoreboard`, слот `Sidebar`) |

`donorTrailsEnabled` — «стоп-кран» для FPS на слабых телефонах: выключение не трогает
`nameTag`, префиксы и join-сообщения, срабатывает на следующем тике `meta-donor`, значение
переживает рестарт (`saveTunables`). Интервал частиц (`DONATIONS.trailEveryTicks` 10) —
константа сборки, она меняется только деплоем.

Числовые ключи ставятся `/sw:meta set <имя> <число>` (валидация: число >= 0), булевы —
`0`/`1` или `true`/`false` (`value === "true" || value === "1"`). В форме «Параметры экономики»
(`src/ui/admin-meta.ts`) для чисел работает textField, а восемь булевых рубильников
(`queueEnabled`, `donorTrailsEnabled`, `quarryEnabled`, `totemsEnabled`, `spawnProtectEnabled`,
`ranksEnabled`, `hudBarEnabled`, `hudSidebarEnabled`) вынесены в отдельные toggle'а
(«Очередь включена», «Частицы-трейлы включены», «стоп-краны модов»): в дропдаун списка
параметров они не попадают, и все галочки сохраняются при любом Submit — поэтому их текущее состояние
подставляется в `defaultValue`. Любая правка уходит в `audit("admin", "eco-config", ...)`
и видна в `ecoSummary()` (строка «частицы трейлов: вкл/выкл»). Проверено стабом:
«тумблер частиц гасит трейлы без рестарта».

## 4. Языки

Все строки идут через `t(player, key, params)` (`src/kernel/i18n`). Словари слоя
подключаются импортом `./messages` из каждого модуля (`src/meta/messages.ts`,
`src/ui/messages.ts`), поэтому ключи регистрируются один раз при старте и не
раздувают бандл дубликатами.

Две половины одной проблемы закрыты двумя проверками стаба. Равенство наборов ключей
ru и en — «словари ru и en синхронны» (`dictionaryStats()`, актуальное число ключей
печатает вывод стаба);
иначе `don.rules.1` и `rules.text` уехали бы в одну локаль. Промах по ключу —
«ни один ключ не уехал в текст без перевода»: `lookup` при отсутствии ключа пишет
`log.warn("i18n", ...)` один раз на ключ и возвращает сам ключ, поэтому опечатка в
`t(player, "menu.titl")` валит и эту проверку, и «нет неожиданных log.warn».

Переходы главного меню под стабом отдельным сценарием (`menu`): подписи кнопок не
разъезжаются с массивом `actions` («Правила мира» присылает правила, «Моя статистика» —
stats-строку), переключение en → ru проходит обратно без потери переводов, а
«Админ-панель» видна только игроку с тегом `admin`.

Переключение языка — в `/sw:menu` («Язык / Language»), значение живёт в профиле.
Языковые имена сущности и пака — `packs/resource_pack/texts/{ru_RU,en_US}.lang`.

## 5. Монетизация и приглашения в этом слое

- донат (`donations.ts`): три тарифа, выдача только руками (`applyTier`), чеки
  (`sw:don:receipts`), цель сбора и споры; за деньги не продаются ₡, предметы и
  ключи к `basic`/`elite` — см. `docs/MONETIZATION.md`;
- косметика (`cosmetics.ts`): 12 позиций, 4 слота (`trail`/`prefix`/`suffix`/`join`),
  покупка только за ₡ (`COSMETIC_CASE` — 3500 ₡), возврат за дубликат через `refundBurn`
  (не через `mint`), `nameTag` = `identityName` (префикс тарифа + prefix + ник + suffix);
- приглашения (`referrals.ts`): код 6 знаков из `player.id` (детерминированно), привязка
  один раз в первые 72 ч, награда обоим только после 2 ч наигранного времени,
  лимиты 3/сутки и 15 000 ₡/месяц, журнал `sw:ref:log`; сброс привязки доступен админу
  из UI («Сбросить привязку приглашения» в админ-донате: выбор онлайн-игрока с `refBy` и
  причина), а не только вызовом `resetBinding`;
- всё это видно в `sw:meta status` (строки `донат:` и `приглашения:`) и в `sw:meta info`
  (там же `disputeLines` и журнал рефералки).

## 6. Ранги и таблица статуса (этап 9)

### Ранги (`src/meta/ranks.ts`)

Ранг — **только косметика**: ни на что, кроме префикса над головой и строки в таблице
статуса, он не влияет. Флаг `ranksEnabled` — единственная кнопка, которая это гасит.

Лестница лежит в `src/meta/config.ts` (`RANKS`, 7 строк: `novice` 10 … `myth` 70) и
состоит из `{ id, order, label, tag, rarity, weight }`. `weight: 0` означает «из кейса не
выпадает» — так помечен `novice`, его выдаёт админ. `order` — единственное, по чему
считается «старше»: лучший ранг = `max(order)` из собранных, а `meta.rank` — только кэш,
который `bestRankOf` пересчитывает на чтении (разошлись — починилось само).

Хранение — в кошельке (`sw:eco:meta`, `PlayerMeta`): `rankOwned: string[]` (всё собранное,
навсегда), `rank` (лучший), `rankAt` (когда изменился), `rankTag` (готовый префикс).
Никаких отдельных документов и реестров: ранг переживает вайп сезона ровно как переживает
кошелёк, а «игрок потерял ранг» превращается в «в кошельке нет строки» — лечится тем же
бэкапом DP, что и монеты.

Кейс (`RANK_CASE`: 2400 ₡ за крутку, ≤ 5 за вызов, возврат 60%):

- монетами платит `burn` до броска, возврат за дубль — `refundBurn` (то есть уменьшает
  `ledger.burned`, а не печатает новые ₡ — эмиссия из-за рангов не растёт вообще, это
  проверяет стаб-шаг «ранги ничего не напечатали»);
- **дубль компенсируется, а не сгорает**: ранг навсегда, «выбросить» его игрок не может;
- тот же текст получает и ранг **ниже** текущего: он попадает в `rankOwned` (коллекция),
  но на ник не выходит — иначе «вытащил Миф, потом упал до Стали» выглядел бы как потеря;
- `rollRanks` проверяет `ranksEnabled` **до** `burn`: на закрытом кейсе не должно уходить
  ни монеты (мутация «гейт после списания» ловится стабом).

`nameTag` остаётся одновладельческим: пишет его только `cosmetics.applyIdentity`, а
`identityName` читает готовый `meta.rankTag`. Поэтому `ranks.ts` импортирует `cosmetics`,
но не наоборот — иначе `donorPrefix`/`metaOf` замкнули бы цикл. Снятие префикса по
стоп-крану делает `syncRankTags()` — он вызывается и на выдаче, и на входе игрока, и
задачей `meta-ranks` (600 тиков), поэтому поворот тумблера виден в игре в пределах
полуминуты без перезапуска.

### Таблица статуса (`src/ui/hud.ts`)

«Таблица на правой части экрана» в API 2.11.0 распадается на две разные витрины, и это
не дизайн-решение, а ограничение движка:

| Что | Чем | Почему |
|---|---|---|
| Ранг, баланс, «за сегодня», «за всё время» | `player.onScreenDisplay.setActionBar` | это единственная **персональная** строка: у `ScreenDisplay` больше нет ничего, кроме title/actionbar/`setHudVisibility` |
| онлайн, топ по ₡, таймер ивента | `world.scoreboard` + `DisplaySlotId.Sidebar` | сайдбар в Bedrock один на весь мир; персонального сайдбара в Script API нет |

Следствия, заложенные в код:

- **число в конце строки не спрятать**: `ScoreboardObjectiveDisplayOptions` умеет только
  `objective` + `sortOrder`, `hideNumber` нет; `displayName` объектива — readonly, поэтому
  заголовок ставится один раз при создании (`CONFIG.hud.sidebarTitle`). Из этого прямо
  следует, что в сайдбар нельзя положить два разных рейтинга: сортировка одна и по числу.
  Поэтому там только топ по монетам (число = ₡), онлайн (число = игроков) и ивент
  (число = минут/секунд);
- строки пишутся **участниками-строками** (fake players): `objective.setScore("§61. §fAlice", 50526)`.
  Список участников — это и есть список строк, поэтому обновление = «задать нужные +
  `removeParticipant` у лишних»; без второй половины в сайдбаре остались бы призрачные
  строки прошлых мест (ловится стабом: «в сайдбаре остались старые строки»);
- `ObjectiveSortOrder.Descending` = 1, `Ascending` = 0 — перепутать их значит молча
  получить «беднейший сверху», поэтому порядок зафиксирован явной проверкой;
- бар не перерисовывается зря: текст сравнивается с последним написанным, а игроки
  проходят по кругу с бюджетом (`CONFIG.hud.budget` 8 за проход). Без кэша это был бы
  `setActionBar` каждому игроку каждые 2 секунды;
- «за сегодня» и «за всё время» берутся из одного аккумулятора (`profiles.playStats`),
  который режет игровое время по полночи **в обе стороны**: и при сейве (`accumulate`),
  и на чтении (живая часть сессии). Иначе в 00:01 строка показывала бы вчерашние минуты
  (это ровно та мутация, которая поймана только после того, как проверка стала читаться
  до `saveProfile`);
- сутки — `dayIndex()` = `floor(Date.now() / 86400000)`, то есть UTC-полночь, та же, что у
  дневных лимитов экономики: «сегодня» в таблице и «сегодня» в лимите минта обязаны
  переворачиваться в одну секунду.

`/sw:hud off` — личное отключение (память, не DP: витрину не нужно переживать рестарт, а
глобальный `hudBarEnabled` остаётся старшим — локальное «on» его не перебивает, и форма
честно отвечает `hud.bar.gated`, а не делает вид, что включила).

## 7. Что требует проверки живым сервером

- фактическая запись big JSON в dynamic properties на BDS 1.26.60 (объём, фрагментация
  ключей, поведение после `restart`);
- отображение кастомной модели босса и частиц на мобильных клиентах (iOS/Android);
- `sound_definitions` из пользовательского ресурспака на телефоне;
- удобство форм на маленьком экране (выпадающие списки длиннее 10 пунктов);
- `nameTag` с §-кодами (`§7[§8бронза§7]§r `) и постфиксом: префикс ставится в
  `applyIdentity`, но как он обрезается в списке игроков и на таб-доске — только живой тест;
- частицы `swipecraft:donor_trail`, `trail_ember`, `trail_frost`, `trail_soul`
  (PNG генерирует `tools/gen-textures.mjs`): виден ли трейл на телефоне и режет ли FPS;
- кастомное сообщение захода (`join`-косметика) уходит в `world.sendMessage` — под боем
  его можно не заметить;
- форма каталога косметики (12 позиций + снятие слотов + журнал): влезает ли в экран;
- видны ли строки сайдбара, собранные из fake-player участников, на реальном
  клиенте (в API participant принимает строку; список игроков и таб-доска
  строковых участников не принимают — это подтверждено только для Sidebar);
- что делает клиент с action bar'ом при открытой форме: HUD пишет раз в 2 секунды,
  и если GUI перекрывает строку, игрок увидит таблицу только после закрытия окна;
- длина строки сайдбара и обрезка §-кодов в имени участника (мок ничего не режет);
- префикс ранга над головой после смерти/респауна: `meta-ranks` вернёт его в
  пределах 30 секунд, но «моргает» ли ник на телефоне — живой тест.

Логику этих мест стаб-харнесс (`npm run stability`) проверяет, но «красиво/не красиво
на телефоне» он проверить не может.
