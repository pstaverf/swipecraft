## 2. День открытия

1. -30 мин: `healthcheck.sh` -> PASS, `systemctl status swipecraft` -> active,
   `df -h` (>= 20% свободно), `sw:meta status` -> "запись на диск: нормально".
2. -15 мин: публикуются реквизиты и пост с адресом, версией, ценами и правилами.
3. -5 мин: `echo "say Сервер открыт" > /run/swipecraft/console.fifo` (FIFO из `run-bds.sh`) -
   проверка, что консоль слушает. `allow-list` не трогаем (он `false`).
4. 0: старт. Первые 30 минут админ в игре, `sw:meta status` каждые 5 минут: "записей: N",
   "не записано на диск" <= 1, "донат: цель ...", "приглашения: кодов выдано N".
5. Каждый час первого дня:
   `journalctl -u swipecraft --since "1 hour" | grep -E "\[error\]|\[warn\]" | tail -20`;
   ошибки - сразу, "мягкие" предупреждения (вида `teleport: измерения нет`) - потом.
6. Вечером: `systemctl start swipecraft-backup.service` (не ждать 05:00 UTC), проверить
   архив и `.sha256`, и записать "что было" (пик онлайна, падения, жалобы) - это материал
   для недели 4 в `docs/PROMOTION.md` §5.
7. Если в логе появились `log.error` из скрипта - не рестартить "для чистоты": сначала
   сохранить кусок лога и вывод `sw:meta status`, иначе состояние уйдёт вместе с хвостом.

## 4. Хранилище состояния: что ломается первым

Мета-слой живёт в dynamic properties мира (чанки + debounce), квота архива балансов 2 МБ:

| Симптом | Причина | Действие |
|---|---|---|
| `хранилище переполнено: N > 2000000, запись приостановлена` в логе + уведомление админам | архив балансов вырос | данные остаются в памяти: не рестартить без нужды; авто-прореживание пустых кошельков (задача `meta-prune`, 60 дней неактивности, только записи без ₡ и без ключей) раз в 21600 тиков; дальше - разбираться, кто нагендил кошельки |
| "не записано на диск: 40" и не уменьшается | флуш не прошёл | `sw:meta flush` вручную, затем смотреть `log.error` |
| после рестарта ₡ "откатились" | процесс убит до `meta-flush` (окно 600 тиков) | останавливать через `stop-bds.sh`, не `kill -9` |
| "выплата по цели прошла", а ₡ не у всех | `goalPayout` платит по реестру `sw:eco:meta` | у игрока без кошелька (ни разу не заходил) награды не будет - это ожидаемо |

## 5. Реагирование: читеры

1. Фиксация: скрин/видео + ник. Без дока не начинаем - это же написано в правилах сообщества.
2. Проверка: `sw:admin` -> "Античит: скоры игроков" (скор и флаги по детекторам), `sw:ac` -
   настройки на ходу. Скор - подсказка, не приговор.
3. Санкция: `sw:admin` -> "Санкции (вручную)" с причиной и сроком; запись уходит в аудит-лог
   (`sw:admin` -> "Аудит-лог").
4. Если затронута экономика/дюп: `docs/ANTIDUPE.md`, проверить `sw:meta status`
   ("эмитировано/сожжено"); при подтверждённом дюпе ₡ - сжигание с причиной в аудит.
5. Донат и бан: бан не отзывает и не возвращает донат автоматически; отзыв тарифа -
   отдельное решение (`revokeTier`), иначе "бан = возврат денег" станет способом
   получить оплату назад.
6. Волна читеров (рейд): временно `allow-list=true` + `allowlist.json`, дальше - по списку
   зашедших в окно рейда из лога. **НЕ ПОДТВЕРЖДЕНО:** как быстро BDS перечитывает
   `allowlist.json` без рестарта.

## 6. Реагирование: DDoS и флуд

Что уже сделано (этап 2/3) - и этого хватает только на объём:

- `deploy/firewall.sh` (ufw: `limit` на новые TCP-соединения 19132/tcp),
  `deploy/nftables-swipecraft.nft` (SYN-flood, conntrack-лимиты),
  `deploy/sysctl-nethernet.conf` (`somaxconn` и лимиты сокетов под 100 сессий);
- анти-флуд на событиях скрипта: рейт-лимиты чата, команд, взаимодействий, дропа
  (`docs/ANTICHEAT.md`). Сырые пакеты Script API не фильтрует - сетевой уровень остаётся
  на провайдере и ядре.

По порядку при атаке:

1. Определить тип: `ss -s`, `journalctl -u swipecraft | tail -50`, снаружи
   `curl http://IP:19132/v1/join`. signaling отвечает, игра нет - проблема в UDP-диапазоне
   или флуде сессий, а не в BDS.
2. Снижать нагрузку, а не рестартить по кругу: `player-idle-timeout` 20-30, временно меньше
   `max-players`, `view-distance` 8, очередь входа (`queueEnabled 1`) чтобы не пускать новых.
   Каждую меру записывать: когда включили, когда сняли.
3. Тикет провайдеру: время старта, тип трафика, снимок `tcpdump` на 19132/tcp и
   `19132-19250/udp`; отдельно спросить лимит пакетов в секунду на UDP - лимит на UDP для
   NetherNet означает "сервер недоступен" даже без атаки.
4. Если включили blackhole - с IP падает всё (сайт, бот, Discord-вебхуки): заранее домен с
   низким TTL и второй адрес только для анонсов.
5. После атаки: `healthcheck.sh`, `sw:meta status`, размер `logs/`, и обязательная сверка
   `sw:don:grants` + `sw:ref:log` - в окно атаки чаще всего и появляются "чудо-выдачи".

## 7. Чего в этом чек-листе нет

- накрутки онлайна, покупных голосов и отзывов, "бустов" рефералки;
- обещаний дат вайпа на год вперёд;
- автоматической выдачи доната: её нет в коде, и здесь она не появляется.
